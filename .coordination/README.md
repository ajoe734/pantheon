# Coordination Handoff

Pantheon uses `.coordination/` as the machine-readable handoff surface for cross-repo delivery.

Structure:

- `requests/`: upstream asks, blockers, and gap reports
- `responses/`: contract-ready notices, Lovable task packets, backend delivery notes, and replayable downstream payloads

Feature-scoped request templates may also live under `requests/` so Pantheon can mirror the same handoff structure into the front-end checkout.

Rules:

- Files are YAML.
- Every payload must include `feature_id` and `type`.
- `bff-gap` requests come from the UI lane when the page cannot be implemented safely against the current BFF contract.
- `ui-done` requests come from the UI lane when Lovable or a front-end editor has finished a screen and wants Pantheon supervisor to pick up review/integration work automatically.
- `contract-ready` responses come from Pantheon when the BFF contract, examples, and dev URL are ready for the front-end lane.
- `lovable-ui-task` responses are generated by the orchestrator after `contract-ready` lands.
- `frontend-feedback` requests come from the front-end lane when the required feedback bundle is ready for Pantheon review or follow-up.
- `backend-delivery` responses come from Pantheon when a contract or BFF change is ready for the next UI cycle.

Current supported payload types:

- `bff-gap`
- `ui-done`
- `frontend-feedback`
- `contract-ready`
- `lovable-ui-task`
- `backend-delivery`
- `needs-runtime`
- `needs-engine`
- `dispatch-request`

Closed-loop rules:

- `lovable-ui-task` keeps backward compatibility with the existing `screen` field, but new packets should also include `workbench`, `screen_id`, `ui_spec_path`, `frontend_change_spec_path`, `required_feedback`, and `delivery_dependencies`.
- `frontend-feedback` is the canonical machine summary for `docs/pantheon-feedback/<feature>/`.
- `backend-delivery` is the canonical machine summary for the next Pantheon-authored delivery bundle.
- Replay must re-dispatch an existing payload path and commit reference. Do not edit payload contents during replay.
