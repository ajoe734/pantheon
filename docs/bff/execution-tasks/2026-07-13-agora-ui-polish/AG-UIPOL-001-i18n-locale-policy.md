# AG-UIPOL-001: Single locale policy — FE i18n keys, BFF stops emitting display copy

## Scope

The hosted Agora shell mixes languages on every tab: English chrome
("Generated from the V11 Winner Branch...", "Position Actions") around
zh-TW copy generated by the BFF ("操盤室提案", "策略總覽", "部分可用",
view purposes/warnings), plus stray mixed strings like "7 個 View".

## Decisions this task must land

1. Locale policy: **zh-TW primary, en fallback** (operator base is zh-TW).
   Document the decision in the execute-plans i18n README; reviewer may
   override with rationale.
2. Ownership: display copy belongs to the FE i18n layer. The BFF returns
   stable keys/enums (`view_kind`, `data_availability: partial|full|missing`,
   warning codes), not display sentences. Existing zh strings in
   `services/control-plane/bff/agora/trading_room/router.py` (9 hardcoded
   titles/purposes) move to FE translations keyed by view/widget id;
   contract additions ride an additive spec extension, never a mutation.

## Work

1. pantheon: replace hardcoded display copy in the trading-room proposal
   generator with keys; keep response shape backward-compatible (keys in new
   fields, old copy fields deprecated-but-present until FE switches, then
   removed in a follow-up).
2. execute-plans: run a mixed-language sweep across `src/agora/` (all three
   tabs + drawers), move literals to the i18n catalog, render everything
   through it. No literal zh inside en sentences or vice versa.
3. Add a CI-level guard test in execute-plans that fails when an
   operator-visible Agora component renders a raw i18n key or a hardcoded
   literal from the audit list.

## Acceptance

- Hosted dev screenshots of all three tabs show one consistent locale.
- BFF proposal payload carries keys/enums; no zh display sentences in
  `router.py` generator code (grep gate).
- i18n guard test green in execute-plans CI.
- Contract tests updated; no frozen bundle mutated.
