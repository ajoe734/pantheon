## Foundation Primitive Use

- `TraceContext` is built from upstream headers when available (`X-Trace-Id`,
  `X-Correlation-Id`, `X-Idempotency-Key`, `X-Request-Id`) and falls back to
  `TraceContext.new` when missing.
- `CommandEnvelope.new` reuses the trace's idempotency key, satisfying the
  envelope's `command idempotency_key must match trace.idempotency_key`
  invariant.
- `IdempotencyRecord.reserve` is followed by `with_status("succeeded", ...)`
  on the success path; the persisted record carries the resulting command id
  via `result_ref`.
- `PolicyDecision.make` and `AuditAction.record` are emitted on accept,
  policy_denial, and validation paths (`bff.command.accepted`,
  `bff.command.policy_denied`, `bff.command.rejected`,
  `bff.command.idempotency_conflict`, and the runtime-manager kill-switch
  accepted action).

## Bundled Out-of-Packet Changes (non-blocking)

The diff also includes adjacent hardening that is not described in the SD-FND-002
handoff packet:

1. CORS middleware setup in `bff/main.py` driven by `PANTHEON_BFF_CORS_ORIGINS`.
   No-op when env var is unset; covered by
   `test_cors_origin_env_parser_trims_and_normalizes`.
2. `_ensure_live_broker_scope_allowed` plus `_LIVE_BROKER_SIGNAL_*` guard,
   gated by `PANTHEON_LIVE_BROKER_ENABLED`. Defaults to deny on live-runtime
   targets. Covered by
   `test_submit_command_rejects_live_runtime_scope_when_disabled`.
3. `RuntimeManagerService._load_ks_state` quarantines a corrupt
   `kill_switch.json` instead of crashing on startup, and `_persist_ks_state`
   now uses a tmp + `os.replace` atomic write.
4. The kill-switch persist order changed: the previous code persisted
   safe-mode state **before** `_execute_kill_switch_binding_action`; the new
   code persists **after** the binding action so it can capture the result
   and idempotency record. Both orderings persist before the function returns,
   so the §11.2 "durable write must precede ack" contract is preserved if
   "ack" is read as the function return. The new ordering does change crash
   semantics: a process crash mid-binding-action will leave no idempotency
   ledger entry on disk, while the prior ordering would have already recorded
   the safe-mode trigger.

These changes do not break any existing test in the verified suite, and each
appears defensive on its own merits. They are nonetheless outside the named
SD-FND-002 packet scope and should be tracked under their own follow-ups so the
foundation envelope adoption is not conflated with broker-scope policy or
kill-switch persistence reform.
