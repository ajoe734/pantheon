### 1. Most of the named deep tasks were not genuinely open

The repo already contains archived `done` snapshots for `DEP-002`, `CAP-002`,
`TEL-002`, `LIN-002`, `EVO-004`, `EVO-005`, and the `OSS-004` EP4 publication
wave. Their implementations, reviews, and closeout messages are present in the
archive and in repo-local evidence.

### 2. `EVO-004` was easy to misread because it had both an older parent task and a later depth recheck

The later `.coordination/reviews/DEPTH-EVO004-review.md` was a real blocker
packet, but it was subsequently resolved and closed through archived
`DEPTH-EVO004`. Current repo truth is not "EVO-004 still open"; it is
"EVO-004 needed a depth recheck and that recheck is now also closed."

### 3. `APP-003` is the real remaining deep backlog, but not in the old shape

`APP-003` should not be interpreted as "all operator/governance/persona/evolution
productization is still unstarted." The reviewed Wave 2 closeout loops were
already removed from the remaining module backlog by `STATE-REBASE-001`.

What remains real is:

- closeout synchronization for already-reviewed surfaces (`APP-003-CLOSEOUT-001`)
- unfinished workbench modules still listed in `WORKBENCH_DELIVERY_BACKLOG.md`

### 4. `OSS-004` is no longer an EP3-only future task

`EXECUTION_PROOF_AND_MATURITY_LEVELS.md` now declares stable `EP4`, and
`docs/deployment/ep4-evidence-packet.md` is the canonical evidence packet.
So `OSS-004` is no longer an open "raise proof someday" placeholder for the
current repo state.
