## Primary capability evidence

- [Claude structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs): schema-constrained output and strict tool schemas support replacing manual extraction/routing format repair. Application validation of semantic correctness/authority still remains.
- [Claude memory tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool): client-side operations backed by storage controlled by the application; supports using a standard memory tool surface but does not delete canonical persistence/authorization.
- [Current DSPy](https://dspy.ai/): DSPy still has optimizer value; evaluate that value rather than assuming native tool calling makes all prompt optimization obsolete.

## Evaluation shape for retiring code

Use a fixed, versioned set of actual governed examples with temporal holdout. Compare old implementation, plain modern LLM, and (only if warranted) optimized LLM. Measure task correctness, abstention/unsupported claims, citation correctness, intent/extraction confusion, cost and p50/p95 latency. Hard gates for permission/source isolation, no hidden live activation, no lost approved records and numerical regression remain mandatory. Delete replaced code after a shadow interval with an explicit rollback point; do not merely add another provider/compatibility layer indefinitely.
