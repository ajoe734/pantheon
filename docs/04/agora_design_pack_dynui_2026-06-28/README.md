# Agora Design Pack Dynamic UI Execution Packet

Date: 2026-06-28

This packet supersedes any attempt to hand-build Agora visual parity from
screenshots alone. The design pack requires a dynamic UI system: the trading
servant generates a complete workspace proposal, the trader can edit views and
widgets, every widget change goes through a revision proposal with before/after
preview, and workspace versions can be compared or rolled back.

## Dynamic UI Invariants

- Strategy Workshop V10 is a strategy co-construction workspace, not a chat
  page and not a static form.
- The first servant response to a long strategy description must insert a
  Strategy Reconstruction Card.
- The Strategy Workshop right rail must track the 12 strategy blocks from V10:
  market scope, insider/branch mapping, winner branch scoring, migration and
  reverse flow, event lead, signal formation, entry and holding, add/reduce/exit,
  sizing and leverage, cost/liquidity/capacity, validation/backtest/refutation,
  and monitoring/update.
- Joining the Trading Room must first create a complete
  `TradingRoomWorkspaceProposal`, not an empty dashboard for the trader to
  assemble manually.
- A proposal must include all views, view thumbnails, widget counts, rationale,
  data availability, warnings, and personalization applied.
- Trading Room widgets are declarative `TradingRoomWidgetSpec` instances backed
  by controlled `ChartSpec` or registry renderers. Production must never eval
  arbitrary React, JavaScript, or HTML generated by an agent.
- Trader layout edits must support drag, resize, remove, restore, add widget,
  change chart, duplicate, and unsaved-change save/discard behavior.
- Clicking a widget must open widget-context-aware servant adjustment. The
  servant must know the widget purpose, data source, fields, filters, time
  window, chart type, strategy/view/evidence context, and current placement.
- The servant cannot directly mutate a widget. It must create a
  `WidgetRevisionProposal` with before/after preview and actions:
  apply, adjust again, keep original and add a modified copy, or cancel.
- Workspace versions are per trader, per strategy, and per strategy version.
  Change log and rollback are required acceptance, not polish.

## Non-Goals

- Do not revive a hand-authored visual parity branch as the delivery path unless
  the owner explicitly asks for that.
- Do not satisfy these tasks with static screenshots, hardcoded mock state, or
  a one-off dashboard.
- Do not expose Management, RuntimeBinding, broker order execution, or
  capital-affecting operations from Agora UI.
