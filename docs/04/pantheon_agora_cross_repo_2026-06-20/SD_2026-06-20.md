## 0. Purpose and Scope

This SD defines the Agora v1 contract foundation so that downstream tasks (AG-XR-002 execute-plans type generation, AG-XR-003 BFF route hardening, etc.) can reference frozen names.

**Freeze rule:** Once AG-XR-001 closes, schema `$id` URIs, capability names, and enum values in this document are frozen. Additive changes require a new version suffix (e.g. `v2`). Renaming or removing a field requires a breaking-change task.

---

## 1. Agora Context

Agora is the human-trader interaction plane of Pantheon. It captures:

- Ask-persona sessions (natural-language queries to trading personas)
- Signal feedback, journal entries, insights, and training examples
- Strategy workshops where a user explores completeness and research readiness
- Dashboard recipes and widget configurations personalised to the operator
- Trading events and intents (observation-only; never route live orders)
- Shadow decisions for imitation-learning ground truth

Agora evidence feeds **Observe** and **Learn** loops only. It never promotes artifacts, modifies live LEAN, or bypasses approval.

## 6. Schema Versioning Policy

- `spec_version: "1.0"` is the initial frozen version for all 13 schemas.
- Additive optional fields are non-breaking and may be added without bumping the version.
- Removing a required field, narrowing an enum, or changing a type is breaking and requires `spec_version: "2.0"` plus a new schema file.
- Schema `$id` URIs are permanent; do not reuse them for changed contracts.

---

## 7. Type Generation Boundary

- **AG-XR-001 (this task):** Defines the 13 JSON schemas and capability manifest. These are the authoritative sources.
- **AG-XR-002:** Generates TypeScript types in `execute-plans/src/lib/agora/` from the schemas defined here. AG-XR-002 must not modify schema content; it only generates derived types.
- **AG-XR-003+:** BFF route hardening and FE wiring tasks consume the capability manifest and OpenAPI.

---

## 8. Security Boundary

- All Agora routes require operator-level auth (same guard as `/bff/management/*`).
- Agora evidence is write-once from the operator's perspective; corrections go through the `actions/{action}` sub-resource pattern.
- Shadow decisions and trading intents must never be routed to live broker; the BFF must reject any such attempt with `AUTHZ_DENIED`.
