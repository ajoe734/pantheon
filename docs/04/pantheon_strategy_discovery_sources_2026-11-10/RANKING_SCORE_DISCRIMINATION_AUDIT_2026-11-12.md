## 1. Exact score reproduction

All line numbers below refer to the audited commit. `services/control-plane/bff/personas/service.py` is abbreviated `personas/service.py` in this report.

The actual entry path is `GET /bff/management/quarterly-ranking` → `PersonaService.get_quarterly_ranking` (16469 onward) → `_compose_quarterly_ranking_context` (15869–15914) → `_pm12_quarterly_ranking_items` (6042–6101) → `_pm12_persona_league_ranking_item` (7480–7493) → `_pm12_persona_league_scores` (5715–5760). Score clamp is `_pm12_clamp_score` (13109–13110); weights are `_PM12_LEAGUE_SCORE_WEIGHTS` (5627–5632).

| Component | Exact operation | Result and interpretation |
| --- | --- | --- |
| PnL | `clamp(50 + pnl * 100)` (5725) | All three values give 100. Unclamped: 1,288,061.6 / 473,050 / 20,750 respectively. Every input ≥ 0.5 saturates; every input ≤ −0.5 bottoms at zero. |
| Risk | `(risk_floor + clamp(100 - drawdown * 400))/2` (5726–5734) | With drawdown 0, drawdown score is 100. Risk 95 therefore implies the `low` floor of 90 under this source version. Missing drawdown would use 65, not 100. |
| Execution | `clamp(fill_rate * 100 - slippage * 2)` when fill rate exists (5735–5740) | `clamp(0 * 100 - 0 * 2) = 0`. Missing fill rate uses neutral 50 instead. |
| Activity | `clamp(20*A + 15*E + 10*C + 5*S + min(2*M,10))` (5741–5746) | One active session, zero completed teaching evaluations, no capability snapshot, one routed strategy and zero memory items give 25. `A/E/C/S/M` come from row summaries, not trade count or runtime count. |
| Overall | `0.35*100 + 0.25*95 + 0.25*0 + 0.15*25` (5748–5755) | `35 + 23.75 + 0 + 3.75 = 62.5`. Tier-3 covers scores ≥55 and <70 (5695–5701; `_pm12_tier_for_score`, 13432–13436). |

The inherited metrics do **not** contain the activity summaries or risk label. The reconstruction explicitly assumes `risk=low` and the above activity tuple. The former is implied by risk 95 and drawdown 0; the latter is a compatible example, **not uniquely recoverable hosted truth**. For example, one completed teaching evaluation plus a capability snapshot also gives 25. Neither `runtime_count=1` nor `total_trades=1` proves an active-session or routed-strategy count. Closing this evidence gap requires the original row summaries; this audit does not invent them.

Input production for these row fields is `_project_persona_league_row` (7146–7208): persona metadata/raw risk → `_normalize_risk_level` (12038–12040, fallback medium); capability store → `_pm12_persona_capability_summary` (5505–5521); active sessions → `_pm12_persona_session_summary` (13009–13095); teaching records → `_pm12_persona_evaluation_summary` (5583–5605); memory items → `_pm12_persona_memory_summary` (13099–13105). Routed counts enter via `_pm12_persona_league_rows` (7391–7407). Activity is infrastructure/participation activity; it does not measure trade profitability or statistical sample size.

The executable evidence invokes the registered quarterly HTTP router with local owner-row and summary adapters. It leaves the production telemetry reducer, scorer, tier selection, PM-12 allocation adapter and snapshot identity calculation intact and asserts all three rows' components, coverage and scores. No score function is copied or mocked. It also checks that entirely missing telemetry remains `None` for PnL/drawdown/fill rate.

It establishes a reachable source path, **not the historical identity of the hosted event**. Process counter reset and a profitable high-water drawdown zero are also reproduced using the actual producer methods.

Real allocation (`calculate_target_allocations:151–220`) permits positive capital only for canary/live and applies caps, factors and exclusions; paper rows are excluded. Equal positive scores do not mechanically prevent real-policy targets or proposals: the calculation can share capacity among equal candidates, subject to its gates.

The existing `calculate_paper_simulation_allocations:224–327` is more limited than a persona competition cycle: it requires **exactly one** eligible paper row with isolated ledger, internal pool and unique binding; it rejects multiple rows (293–296), sets target weight **1.0** (300), and returns `requires_human_approval=True` (325). The function is not a three-persona shared paper budget allocator. Its current approval semantics differ from the newer design's paper autonomy (P-4); this audit neither removes the guard nor claims the new design is implemented.

Thus the supplied zero Capital records are consistent with absent automatic orchestration. They do not prove the evaluator endpoint was never manually called, because evaluation itself returns lines without creating those records. Hosted history and external cron configuration were deliberately not inspected.
