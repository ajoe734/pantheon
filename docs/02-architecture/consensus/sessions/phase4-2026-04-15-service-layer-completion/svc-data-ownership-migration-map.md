# SVC-DATA-OWNERSHIP-MIGRATION-MAP

Last updated: 2026-04-29
Status: execution artifact for `SVC-DATA-OWNERSHIP-MIGRATION-MAP`
Scope: code-backed inventory of default compose file-backed service stores and their Postgres migration slices

## Reading Rule

This is a migration map, not a runtime behavior change. The current default single-VM stack keeps the existing JSON/JSONL and volume stores until a later store pilot explicitly adds an optional Postgres-backed implementation.

The ownership rule remains the L1 policy in `DATABASE_OWNERSHIP_AND_SHARED_CLUSTER_POLICY.md`: shared Postgres cluster, single write owner per table, and non-owner services using read-only DB roles or owner service APIs for writes.

Default compose means services in `docker-compose.yml` without an explicit profile. `postgres`, `minio`, `nats`, `signal-store`, `smoke-stack`, and profiled `openclaw-gateway` storage are infrastructure/runtime stores and are not JSONL-to-Postgres service migration candidates.

## Pilot Order

1. `consultation-svc` optional Postgres store.
   This is the first pilot because it is already isolated behind `ConsultationStore`, has append/replay lifecycle semantics, has a dedicated compose volume, and is a direct dependency of `SVC-CONSULTATION-POSTGRES-STORE-PILOT`.
2. Source ingest plus search reference stores.
   Migrate `source-ingest` first, then switch `search-svc` evidence reads to the owner API/read role. Search must not write source evidence rows.
3. Runtime/governance/capital/deployment/evolution/incident cluster.
   These share command and evidence boundaries, so migrate after the first pilot proves the env-gated store abstraction and rollback pattern.
4. Research/training/feedback/BFF local state.
   These are lower priority because some are safe wrappers with production adapters disabled or local control-plane caches/receipts rather than canonical domain stores.

## Rollback Path

Every store pilot should be opt-in by explicit env such as `PANTHEON_<SERVICE>_STORE_BACKEND=postgres` or a service-specific equivalent. JSON/JSONL remains the default until the pilot is reviewed.

Rollback for a pilot:

1. Stop the service or drain writes.
2. Set the store backend env back to `jsonl` or unset the Postgres backend env.
3. Restart the service against the existing named volume.
4. Keep Postgres rows read-only for investigation; do not dual-write corrections unless a follow-up migration task owns reconciliation.

The pilot must include a one-way bootstrap/import command or clearly documented manual import from the JSON/JSONL volume into owner tables. It must not grant non-owner write roles as a shortcut.

## Acceptance Notes

- The inventory is backed by root compose env/volume wiring and the concrete store implementations listed in the evidence column.
- Each target table family has one write-owner service.
- Cross-service direct writes are disallowed; owner service APIs or read-only DB roles are the only allowed sharing mechanisms.
- No runtime code, compose defaults, or service behavior changed in this task.
