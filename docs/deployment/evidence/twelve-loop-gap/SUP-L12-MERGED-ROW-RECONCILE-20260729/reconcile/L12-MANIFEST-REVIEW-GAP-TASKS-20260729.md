## Why Normal Owner Closeout Cannot Recover This Row

`ai_status.py` derives the expected commit trailers from the *current* canonical
row (`expected_fields = {"LLM-Agent": actor, "Task-ID": task_id, "Reviewer":
canonical_agent_name(task["reviewer"])}`) and applies them to the worktree HEAD
subject and body.

The merged delivery commit `7b68b423590855ea8d39ea718103b29a612a948a` carries:

```

Task-ID: L12-MANIFEST-REVIEW-GAP-TASKS-20260729
Reviewer: Antigravity
```

while the canonical row is owner `Antigravity`, reviewer `Claude2`. The commit
is already merged and immutable, so the mismatch cannot be repaired in place;
`done` fails closed forever on this delivery. The row is additionally `blocked`,
a status `command_done` does not accept, and `command_approve` refuses any row
that is not in `review`.

`reconcile_merged_done` is the designed recovery: it accepts `blocked` directly
and validates the merged evidence and merged delivery instead of the trailers.
