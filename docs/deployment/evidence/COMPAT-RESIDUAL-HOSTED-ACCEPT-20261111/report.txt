Pantheon 新舊實作、相容尾巴與開發偏移盤點
工作版本：2026-11-11；已決定執行的來源清理均已合併，實際部署驗收與最終報告尚未完成。

判斷方法
每項分開判斷原有能力、新實作的用途、仍有誰呼叫、資料／回復需求，再決定刪留。測試或路由清單自己引用自己，不等於產品仍需要。沒有 access log 不宣稱零流量；沒有掃到檔案不等於沒有資料。
以下「改善」是依來源、契約及操作證據判讀；未量測的效能提升不作宣稱。對缺少原始決策記錄的重構，不猜測開發者動機，也不把重構本身當作新產品功能。

A01 SourceIngestionRuntime 與舊 main.py globals
新實作把 store、lock、config 放到明確 runtime context，讓服務不必從入口模組反查狀態。保留的 _active_attr、sys.modules、__code__ 分派及 forwarding aliases 原本用來接舊呼叫與舊測試，延長後形成理解與修改負擔。
處置：遷移呼叫者與測試後刪除這些相容機制，保留既有 ingestion 能力與 context。這是清理重構留下的尾巴，沒有另寫 ingestion 引擎。
來源交付：Pantheon PR #7056；merge 757a804536d5d10710a6f1e07d53bba767efaad3。

A02 Agora audit 的兩個 writer
AgoraAuditStore 與 Governance decision store 的資料 schema／業務語意不同，不能因都叫 audit 就當作重複儲存直接刪除。真正多餘的是 Agora/management 寫入時又退回 read_store 的第二條 writer。
處置：統一經既有 AgoraAuditStore 寫入，刪 read_store writer fallback，保留原有 JSONL 儲存。改善是寫入權責一致；沒有新增另一套 audit 平台。
來源交付：Pantheon PR #7053；merge 83ebb82ec33c5d5d31eb60b59bc1564dae9c2dad。

A03 Management 新中心頁與舊頁／網址

處置：移除死的 PromotionAllocation 檔案，遷移前端自行產生的舊連結；保留仍被嵌入的元件。網址 redirect 有實際來源需求：BFF services/control-plane/bff/pm12/service.py 的 holding links 仍產生 /management/performance-attribution?...，不能把整組 redirect 視為零使用。
